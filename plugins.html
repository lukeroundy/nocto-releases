Nocto Plugin SDK

Extend Nocto with native C/C++ DLLs or shader-only filters. ABI version 2 (ABI 1 plugins still load), SDK 1.1. Nocto 0.8.0 and newer (Windows and Linux) load ABI 1 and ABI 2 plugins; plugins that use ABI 2 features need Nocto 0.8.0 or newer (see ABI 2), while plugins that stay on ABI 1 also run on Nocto 0.4.0+ (Linux: 0.6.0+).

Download SDK (zip) nocto_plugin.h

A plugin is a Windows x64 DLL (or, since Nocto 0.6.0, a Linux x86_64 shared library, see Linux) that exports a small plain-C interface defined in a single header, nocto_plugin.h (no dependencies besides <stdint.h>). All GPU objects are Direct3D 11 objects on Nocto's own device, passed as void*, so frames never leave the GPU. Simple video effects need no compiler at all: a JSON manifest plus an HLSL pixel shader is a complete plugin.

Nocto draws all settings UI for you from a list of typed properties, logs everything to plugins.log, and catches crashes inside plugin callbacks so a bad plugin cannot take a recording down with it (within limits).

ABI, versioning & entry points

NOCTO_EXPORT uint32_t nocto_plugin_abi(void);                                  // required: return NOCTO_PLUGIN_ABI
NOCTO_EXPORT int      nocto_plugin_load(const nocto_host* host, nocto_plugin_info* info);  // required: 1 = ok, 0 = fail
NOCTO_EXPORT void     nocto_plugin_unload(void);                               // optional

In C++ declare them extern "C" so the names are not mangled. Load sequence:

  1. Nocto LoadLibraryExs the DLL (search: the DLL's own folder, then system default dirs; put private dependencies next to your DLL).
  2. It looks up nocto_plugin_abi and nocto_plugin_load; if either is missing the file is reported as not a Nocto plugin and unloaded.
  3. nocto_plugin_abi() must return 1u or 2u (the host's NOCTO_PLUGIN_ABI is 2; return 2 if you use the ABI 2 APIs). Any other value: ABI n not supported (host ABI 2), the DLL is unloaded.
  4. nocto_plugin_load(host, info) is called once. Fill info and call host->register_*. Return 1. Returning 0 marks the plugin failed (nocto_plugin_load returned 0) and drops anything it registered.

Versioning rules. The ABI number changes only on incompatible changes (struct layout, calling conventions, semantics). Within an ABI version new functionality will be added only through new exports or new register_* features, never by changing existing structs. Compile against the header shipped with the ABI you target; check host->abi if you want to refuse unknown hosts. host->host_version is a human-readable string (currently "Nocto 1.0", the plugin host version, not the app version) for logging only — don't parse it.

nocto_plugin_unload is resolved but currently never called: DLLs stay mapped until the process exits, and Nocto does not call into plugins at shutdown. Don't put essential cleanup (flushing files) there; do it in destroy/stop.

Sources

typedef struct nocto_source_desc {
    const char* id;          /* unique within the plugin */
    const char* name;        /* "Add source" menu label */
    const nocto_prop* props; uint32_t prop_count;
    void* (*create)(void* device, const float* values);
    void (*destroy)(void* inst);
    void (*update)(void* inst, const float* values);                 /* settings changed (optional) */
    void* (*render)(void* inst, void* context, double time_sec, uint32_t* w, uint32_t* h);
} nocto_source_desc;
create(device, values) — required
device is Nocto's ID3D11Device* (do not Release it). Return your instance, or NULL on failure (the source shows plugin source unavailable). Called lazily on the render thread the first time the source is drawn.
destroy(inst) — optional
Free everything. Called when the source is removed, the scene is unloaded, or its settings change (see below).
update(inst, values) — optional
Reserved. Nocto 0.4 does not call it: changing a plugin source's settings destroys the instance and creates a new one with the new values. Implement it anyway if you can update cheaply; a future version may call it instead of recreating.
render(inst, context, time_sec, w, h) — required
Called once per rendered frame. context is the immediate ID3D11DeviceContext*. Return an ID3D11ShaderResourceView* you own and set *w/*h to its size, or return NULL to draw nothing this frame. time_sec is seconds since plugins were loaded (monotonic, QPC). Nocto does not AddRef the view; it must stay valid until your next render or destroy.

Video filters

typedef struct nocto_video_filter_desc {
    const char* id; const char* name;
    const nocto_prop* props; uint32_t prop_count;
    void* (*create)(void* device);
    void (*destroy)(void* inst);
    int (*process)(void* inst, void* context, void* in_srv, void* out_rtv, uint32_t w, uint32_t h, const float* values, double time_sec);
} nocto_video_filter_desc;
create(device) — optional
Called once per filter slot (source + position in its filter list) the first time it runs. Returning NULL is not treated as failure: process is still called with inst == NULL, so check for it. If create is absent, inst is always NULL.
destroy(inst) — optional
Reserved: in 0.4 filter instances live until Nocto exits and destroy is not called. Keep per-instance GPU memory modest.
process(inst, context, in_srv, out_rtv, w, h, values, time_sec) — required
Read in_srv (ID3D11ShaderResourceView*), write all of out_rtv (ID3D11RenderTargetView*), both w×h. Return 1 if you wrote the output, 0 to pass the input through unchanged (then the output contents are ignored). values are the current settings (changes take effect on the next frame, no recreate).

D3D11 texture contract

  • Alpha is straight. Nocto composites with SRC_ALPHA / INV_SRC_ALPHA. If your shader works in premultiplied space, divide by alpha before writing.
  • Formats of filter input and output are identical; query ID3D11ShaderResourceView::GetDesc if you need to know which one you got. Write code that works for both (a shader that only does arithmetic on float4 does).
  • Device/context: use only Nocto's device and the passed context (the immediate context). Nocto holds the device lock while calling you: do not lock it again, do not call Flush/Map with waits on GPU work, do not block. Create resources in create, not every frame.
  • Pipeline state is not preserved. Before calling a video filter Nocto leaves arbitrary state bound; set everything you use (render target, viewport, blend, rasterizer, shaders, IA, constant buffers, samplers, SRVs). Nocto restores its own state afterwards. Unbind in_srv from your PS slot when done (the texture becomes a render target for the next filter).
  • Don't keep in_srv/out_rtv beyond the call: they are ping-pong targets, recreated on resize.
  • Filter dimensions are the source's native size (up to 16384×16384).

Audio filters

typedef struct nocto_audio_filter_desc {
    const char* id; const char* name;
    const nocto_prop* props; uint32_t prop_count;
    void* (*create)(uint32_t sample_rate, uint32_t channels);
    void (*destroy)(void* inst);
    void (*process)(void* inst, float* samples, uint32_t frames, const float* values);
} nocto_audio_filter_desc;
create(sample_rate, channels) — optional
One instance per audio source the filter is added to. Rate and channel count are fixed for the instance's life (the chain is rebuilt if the configuration changes). NULL is allowed as instance.
destroy(inst) — optional
Called when the filter is removed/reordered, the source goes away or the audio settings change.
process(inst, samples, frames, values) — required
Modify frames × channels samples in place. Must be real-time safe: no allocation, locks, I/O or logging per call.

Audio buffer format

  • 32-bit float, interleaved (L R L R …), nominal range ±1.0 (not clipped between filters).
  • channels = 2 (stereo) in Nocto 0.4; sample_rate = Settings › Audio sample rate (48000 by default, 44100 possible).
  • Chunks are 10 ms (sample_rate / 100 frames, 480 at 48 kHz) — but always use the frames argument; don't hard-code it.
  • Filters run per source before mixing, on the mixer thread. Output audio callbacks receive the final mix in the same format with pts in 100 ns QPC units.
  • Filters must not add latency (Nocto does not compensate plugin latency).

Outputs

typedef struct nocto_output_desc {
    const char* id; const char* name;
    const nocto_prop* props; uint32_t prop_count;
    void* (*start)(void* device, const float* values);
    void (*stop)(void* inst);
    void (*video)(void* inst, void* context, void* canvas_srv, uint32_t w, uint32_t h, int64_t pts);
    void (*audio)(void* inst, const float* samples, uint32_t frames, uint32_t sample_rate, uint32_t channels, int64_t pts);
} nocto_output_desc;
start(device, values) — required
Called on the UI thread when the user presses Start in File › Plugins… (with default values). Return the instance, NULL = start failed.
stop(inst) — optional
Called on Stop (UI thread). Free the instance. Not called at app exit.
video(inst, context, canvas_srv, w, h, pts) — optional
Every program frame, render thread, device locked. canvas_srv is valid only during the call: copy it (CopyResource into your own texture) if you need it later; read back asynchronously with staging textures over several frames — never stall. pts: 100 ns QPC ticks. A frame may be skipped if the plugin host is busy (start/stop in progress).
audio(inst, samples, frames, sample_rate, channels, pts) — optional
Mixed program audio, audio thread, read-only buffer. Video and audio come on different threads — synchronise your own state.

Load paths, enable / disable

  • Folders, in order: %LOCALAPPDATA%\Nocto\plugins\ (per user; File › Plugins… › Open user plugins folder), then <Nocto.exe folder>\plugins\ (shipped samples).
  • Every *.dll is a code plugin and every *.json a shader manifest; sorted by name within a folder. A file name loads only once: the per-user copy wins and the other is logged as skipped. Subfolders are not scanned — put a DLL's own dependencies next to it.
  • Plugins load at startup. In File › Plugins… each has a checkbox: disable stops every call into it immediately (sources draw nothing, filters pass through, its menu entries disappear) and is remembered in settings; the DLL stays mapped until restart. Enable loads a not-yet-loaded plugin right away.
  • To update a DLL: close Nocto (the file is locked while mapped), replace it, start Nocto.

Crash handling and its limits

Every call into a plugin (including nocto_plugin_abi and nocto_plugin_load) runs inside a structured-exception (SEH) guard. On an access violation or any other SEH exception the plugin is marked Crashed and logged as sample.dll: crashed in video filter process (exception 0xC0000005) - plugin disabled. No further calls are made: sources draw nothing, filters pass video/audio through, outputs stop being fed. Recording and streaming continue. A crashed plugin can only be re-enabled by restarting Nocto.

This is a safety net, not a sandbox. It cannot help when a plugin:

  • corrupts memory (heap or Nocto's) without faulting immediately — Nocto may crash later anywhere;
  • hangs or blocks (deadlocks the render/audio thread → frozen app, dropped frames);
  • throws a C++ exception across the C boundary (catch everything inside your callbacks), calls abort()/exit(), or stack-overflows badly;
  • leaves the D3D device removed (e.g. TDR from an endless shader loop);
  • has no exception: wrong results, leaked GPU memory.

Only install plugins you trust; they run with full user rights inside Nocto.

What Nocto provides

The file is compiled as ps_5_0 (optimisation level 3) when the plugin loads; errors appear in the Plugins window and log. Nocto prepends exactly:

Texture2D src : register(t0);
SamplerState samp : register(s0);
cbuffer NoctoParams : register(b0) { float4 noctoP[4]; float4 noctoInfo; };
#define PARAM(i) (noctoP[(i) / 4][(i) % 4])
#define TEXSIZE (noctoInfo.xy)
#define TIME (noctoInfo.z)
#line 1
  • src: the input (format/alpha per the texture contract); samp: linear filtering, clamp.
  • PARAM(i): manifest param i (0-based, declaration order); TEXSIZE: size in pixels; TIME: seconds.
  • Nocto draws a fullscreen triangle with blending off. Your entry gets (float4 pos : SV_Position, float2 uv : TEXCOORD0) (uv 0..1, top-left origin) and returns float4 : SV_Target (straight alpha). Don't redeclare b0/t0/s0.

vignette.hlsl

// Nocto shader filter. Provided by the host: Texture2D src, SamplerState samp, PARAM(i) (manifest params in order),
// TEXSIZE (float2 pixels), TIME (seconds). Input: SV_Position + TEXCOORD0 (0..1). Output: straight-alpha colour.
float3 Unpack(float c) { uint u = (uint)c; return float3((u >> 16) & 255, (u >> 8) & 255, u & 255) / 255.0; }
float4 main(float4 pos : SV_Position, float2 uv : TEXCOORD0) : SV_Target {
    float4 c = src.Sample(samp, uv);
    float2 d = (uv - 0.5) * float2(TEXSIZE.x / TEXSIZE.y, 1.0);
    float r = length(d) / (0.5 * length(float2(TEXSIZE.x / TEXSIZE.y, 1.0)));
    float v = 1.0 - PARAM(0) * smoothstep(PARAM(1) * 0.5, PARAM(1) * 1.33, r);
    c.rgb = lerp(Unpack(PARAM(2)), c.rgb, v);
    return c;
}

Copy both files into %LOCALAPPDATA%\Nocto\plugins, restart Nocto (or enable it), then add Vignette (sample shader) from a source's Filters.

Editor effects, keyframes & masks

Since 0.5.0 the video editor has a GPU effect stack per clip (Inspector > Effects (GPU)). Built-in effects and plugin video filters use one parameter model: the same {id, label, type, default, min, max} entries as a shader-only manifest. Every loaded plugin video filter (shader-only or DLL) appears in the editor's + Add effect > Plugins menu automatically, with no extra code.

What the editor adds on top of your filter

  • Keyframes on every param. Each param row has a keyframe diamond: click to add or remove a key at the playhead, right-click for Linear, Ease in/out or Hold and to jump to the previous or next key. Keys are drawn on the selected clip in the timeline, where you can drag them to retime. Nocto evaluates the curve on the CPU each frame and passes the value through PARAM(i) (DLL filters receive it in values[i]). color params interpolate per channel.
  • Masks. Any effect can be limited to a rectangle or ellipse (centre, size, feather, rotation, invert; all keyframable). The host renders your filter, then blends lerp(input, yourOutput, mask). Your shader doesn't need any mask code.
  • Deterministic time. In the editor TIME (and the t argument of DLL process) is clip-local seconds, so previews and exports match frame for frame. On live sources it stays the app clock.
  • Stack order. Effects run top to bottom at the clip's native resolution, before transform/crop/opacity and transitions are applied on the canvas.

Built-in shader header

Built-ins compile with the plugin header above plus two extras. Plugins don't get these: #define PASS (noctoInfo.w) (multi-pass effects) and Texture3D lut3d : register(t1). If you write your own effect and need more than one pass, chain two plugin filters.

Project file

Effects are saved in the .gprproj JSON per clip as {"id","key","enabled","params":[{"id","v","keys":[{"t","v","interp"}]}],"path","maskShape","maskInvert","mask":[...]}. t is clip-local seconds and interp is 0 linear, 1 ease, 2 hold. Params are matched by id, so adding params to your manifest later keeps old projects working: missing ids use your default.

nocto.storage v1Per-plugin settings JSON (up to 1 MiB) and secrets (key [A-Za-z0-9_.-]{1,64}, value up to 2500 bytes; Windows Credential Manager, or the Secret Service on Linux with a 0600 file fallback). Secrets are never exported or logged.
nocto.net v1Async HTTP(S) and WebSocket (ws/wss) clients with TLS. http_cancel guarantees no later callback; ws_open calls on_close exactly once, also when the connection fails.

Threads. Panel draw, menu items, post_to_ui and timer tasks, HTTP completions and WebSocket events all run on the UI thread, one after another, so state touched only from them needs no locks. Never block in them. post_to_ui, post_to_ui_after, cancel_task and get_stream_state are the only calls valid from another thread. All callbacks are crash-guarded.

Example. The full Twitch plugin source ships in the SDK zip (samples/twitch): a menu, two dock panels, OAuth device code flow, tokens in secrets, the Helix API and EventSub WebSocket chat. The sample api_demo shows each API in about 300 lines. Full reference: docs/PLUGINS.md in the SDK zip, and the comments in nocto_plugin.h.

Installing plugins & the zip format

Users: File › Plugins… › Install from .zip… or Browse plugins…. Nothing is fetched until the user presses Load plugin list; every install asks first, warns that plugins run with Nocto's access to the PC, and downloads from the list are checked against the SHA-256 in plugins.json. Installs and removals finish at the next start of Nocto.

Authors: a plain zip, flat or with one wrapping folder, holding only *.dll (Windows), *.so (Linux), *.json, *.hlsl, *.glsl, *.md, *.txt. Keep the file stem equal to the catalog id so Nocto can tell it is installed. Nocto refuses other file types, absolute or .. paths, reserved Windows names, duplicate names, more than 64 files, more than 64 MiB per file or 128 MiB total, bad CRCs, and zips with nothing for the running OS. To list your plugin in the library add an entry to plugins.json with platform (windows-x64, windows-arm64, linux-x64 or any), url (https, or relative) and a 64-hex sha256.

Linux plugins (.so)

Nocto for Linux (x86_64 AppImage, since 0.6.0) loads the same plugins through the same ABI; Nocto 0.8.0 on Linux and on Windows loads both ABI 1 and ABI 2 plugins, including the ABI 2 panels, settings, secrets and network APIs. The header, the property system, audio filters, outputs, hotkeys and the editor effects work unchanged. What differs is the graphics API and the file layout.

  • Format and folders: code plugins are shared libraries (*.so, loaded with dlopen) and shader manifests are *.json as on Windows. Folders: ~/.local/share/Nocto/plugins/ (or $XDG_DATA_HOME/Nocto/plugins, or $NOCTO_CONFIG_DIR/plugins if set) and the plugins folder next to the nocto binary (inside the AppImage that is read-only; use the per-user folder).
  • No D3D11: every device / context argument is NULL and an OpenGL 3.3 core context is current on the calling thread. A “shader resource view” is a GL_TEXTURE_2D name and a “render target view” is a framebuffer object name, both passed as (void*)(uintptr_t)name. Source textures are RGBA8, straight alpha, row 0 = top of the picture. For video filters in is a texture name and out is an FBO that is already bound with the viewport set; draw into it and leave nothing bound. Nocto saves and restores its own GL state around every call.
  • Build: g++ -shared -fPIC -O2 -Iinclude my_plugin.cpp -o my_plugin.so -lGL (CMake: add_library(x MODULE ...) with PREFIX ""). The sample in the SDK zip builds for both platforms from the same source.
  • Shader-only plugins: the same HLSL file is translated to GLSL by the host. Alternatively give the manifest "glsl": "file.glsl" instead of "shader" and write vec4 fx(vec4 pos, vec2 uv) directly (src, PARAM(i), TEXSIZE, TIME are available). A compile error is shown in the Plugins window and the plugin is not loaded.
  • Crash isolation uses signal handlers (SIGSEGV, SIGBUS, SIGFPE, SIGILL, SIGABRT), so a fault in a callback disables the plugin like on Windows. A stack overflow is not caught.
  • Not available on Linux: register_script_engine (returns 0). The HDR canvas is not available either (Linux output is SDR).

// Template Nocto plugin: an "Invert" video filter (D3D11 pixel shader) plus a hotkey action.
// Rename ids/names, then build with the SDK CMakeLists.txt. See https://lukeroundy.github.io/nocto-releases/plugins.html
#include "nocto_plugin.h"
#include <d3d11.h>
#include <d3dcompiler.h>
#include <cstring>

static const nocto_host* g_host;
static void Log(int level, const char* m) { if (g_host) g_host->log(g_host->plugin, level, m); }

static const char kShader[] = R"(
cbuffer P : register(b0) { float amount; float3 pad; };
Texture2D src : register(t0); SamplerState samp : register(s0);
struct V { float4 pos : SV_Position; float2 uv : TEXCOORD0; };
V vs(uint id : SV_VertexID) { V o; o.uv = float2((id << 1) & 2, id & 2); o.pos = float4(o.uv * float2(2, -2) + float2(-1, 1), 0, 1); return o; }
float4 ps(V i) : SV_Target { float4 c = src.Sample(samp, i.uv); c.rgb = lerp(c.rgb, 1.0 - c.rgb, amount); return c; }
)";

struct Invert {
    ID3D11VertexShader* vs = nullptr; ID3D11PixelShader* ps = nullptr;
    ID3D11Buffer* cb = nullptr; ID3D11SamplerState* samp = nullptr;
};
template <class T> static void SafeRelease(T*& p) { if (p) { p->Release(); p = nullptr; } }
static void InvertDestroy(void* p) {
    auto* f = static_cast<Invert*>(p);
    if (!f) return;
    SafeRelease(f->vs); SafeRelease(f->ps); SafeRelease(f->cb); SafeRelease(f->samp);
    delete f;
}
static bool Compile(const char* entry, const char* target, ID3DBlob** out) {
    ID3DBlob* err = nullptr;
    HRESULT hr = D3DCompile(kShader, sizeof(kShader) - 1, "my_plugin", nullptr, nullptr, entry, target, 0, 0, out, &err);
    if (FAILED(hr)) Log(NOCTO_LOG_ERROR, err ? (const char*)err->GetBufferPointer() : "D3DCompile failed");
    if (err) err->Release();
    return SUCCEEDED(hr);
}
static void* InvertCreate(void* device) {
    auto* dev = static_cast<ID3D11Device*>(device);
    auto* f = new Invert;
    ID3DBlob* vsb = nullptr; ID3DBlob* psb = nullptr;
    bool ok = Compile("vs", "vs_5_0", &vsb) && Compile("ps", "ps_5_0", &psb) &&
              SUCCEEDED(dev->CreateVertexShader(vsb->GetBufferPointer(), vsb->GetBufferSize(), nullptr, &f->vs)) &&
              SUCCEEDED(dev->CreatePixelShader(psb->GetBufferPointer(), psb->GetBufferSize(), nullptr, &f->ps));
    if (vsb) vsb->Release();
    if (psb) psb->Release();
    D3D11_BUFFER_DESC bd{16, D3D11_USAGE_DYNAMIC, D3D11_BIND_CONSTANT_BUFFER, D3D11_CPU_ACCESS_WRITE};
    D3D11_SAMPLER_DESC sd{}; sd.Filter = D3D11_FILTER_MIN_MAG_MIP_LINEAR;
    sd.AddressU = sd.AddressV = sd.AddressW = D3D11_TEXTURE_ADDRESS_CLAMP; sd.MaxLOD = D3D11_FLOAT32_MAX;
    ok = ok && SUCCEEDED(dev->CreateBuffer(&bd, nullptr, &f->cb)) && SUCCEEDED(dev->CreateSamplerState(&sd, &f->samp));
    if (!ok) { InvertDestroy(f); return nullptr; }   // NULL: Nocto passes the video through
    Log(NOCTO_LOG_INFO, "Invert filter created");
    return f;
}
static int InvertProcess(void* p, void* context, void* in_srv, void* out_rtv, uint32_t w, uint32_t h, const float* values, double) {
    auto* f = static_cast<Invert*>(p);
    if (!f) return 0;                                  // create failed -> pass through
    auto* ctx = static_cast<ID3D11DeviceContext*>(context);
    D3D11_MAPPED_SUBRESOURCE m{};
    if (FAILED(ctx->Map(f->cb, 0, D3D11_MAP_WRITE_DISCARD, 0, &m))) return 0;
    float c[4] = {values[0], 0, 0, 0}; memcpy(m.pData, c, sizeof c);
    ctx->Unmap(f->cb, 0);
    // Nocto does not preserve pipeline state: set everything this draw uses.
    auto* rtv = static_cast<ID3D11RenderTargetView*>(out_rtv);
    auto* srv = static_cast<ID3D11ShaderResourceView*>(in_srv);
    D3D11_VIEWPORT vp{0, 0, float(w), float(h), 0, 1};
    ctx->OMSetRenderTargets(1, &rtv, nullptr);
    ctx->OMSetBlendState(nullptr, nullptr, 0xFFFFFFFF);
    ctx->RSSetViewports(1, &vp);
    ctx->RSSetState(nullptr);
    ctx->IASetInputLayout(nullptr);
    ctx->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
    ctx->VSSetShader(f->vs, nullptr, 0);
    ctx->PSSetShader(f->ps, nullptr, 0);
    ctx->PSSetConstantBuffers(0, 1, &f->cb);
    ctx->PSSetSamplers(0, 1, &f->samp);
    ctx->PSSetShaderResources(0, 1, &srv);
    ctx->Draw(3, 0);
    ID3D11ShaderResourceView* nul = nullptr;
    ctx->PSSetShaderResources(0, 1, &nul);           // unbind the input before Nocto reuses it as a target
    return 1;
}
static const nocto_prop kInvertProps[] = {{"amount", "Amount", NOCTO_PROP_FLOAT, 1.f, 0.f, 1.f}};
static const nocto_video_filter_desc kInvert = {"invert", "Invert (my plugin)", kInvertProps, 1, InvertCreate, InvertDestroy, InvertProcess};

static const nocto_hotkey_desc kHello = {"hello", "My plugin: say hello", Hello, nullptr};

extern "C" NOCTO_EXPORT int nocto_plugin_load(const nocto_host* host, nocto_plugin_info* info) {

// ---------------- source: solid colour + moving bar (top 10%), CPU-filled BGRA texture ----------------
struct Bars {
#ifdef _WIN32
    ID3D11Device* dev; ID3D11Texture2D* tex = nullptr; ID3D11ShaderResourceView* srv = nullptr;
#else
    GLuint tex = 0;
#endif
    uint32_t w = 640, h = 360; uint32_t color; float speed; std::vector<uint32_t> px;
};
static const nocto_prop kBarsProps[] = {
    {"color", "Background", NOCTO_PROP_COLOR, float(0x3080FF), 0, float(0xFFFFFF)},
    {"speed", "Bar speed", NOCTO_PROP_FLOAT, 0.25f, 0.f, 2.f},
    {"width", "Width", NOCTO_PROP_INT, 640, 64, 1920},
};
static void BarsApply(Bars* b, const float* v) { b->color = (uint32_t)v[0]; b->speed = v[1]; b->w = (uint32_t)v[2] & ~1u; if (b->w < 64) b->w = 64; b->h = b->w * 9 / 16; }
static void* BarsCreate(void* device, const float* v) {
#ifdef _WIN32
    auto* b = new Bars{static_cast<ID3D11Device*>(device)};
    BarsApply(b, v);
    D3D11_TEXTURE2D_DESC td{b->w, b->h, 1, 1, DXGI_FORMAT_B8G8R8A8_UNORM, {1, 0}, D3D11_USAGE_DEFAULT, D3D11_BIND_SHADER_RESOURCE};
    if (FAILED(b->dev->CreateTexture2D(&td, nullptr, &b->tex)) || FAILED(b->dev->CreateShaderResourceView(b->tex, nullptr, &b->srv))) { delete b; return nullptr; }
#else
    (void)device;   // Linux: NULL; a GL 3.3 context is current
    auto* b = new Bars;
    BarsApply(b, v);
    glGenTextures(1, &b->tex); glBindTexture(GL_TEXTURE_2D, b->tex);
    glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR); glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
    glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE); glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
    glPixelStorei(GL_UNPACK_ALIGNMENT, 4);
    glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA8, (GLsizei)b->w, (GLsizei)b->h, 0, GL_BGRA, GL_UNSIGNED_BYTE, nullptr);
#endif
    b->px.resize(size_t(b->w) * b->h);
    char m[96]; snprintf(m, sizeof m, "Color Bars created %ux%u", b->w, b->h); Log(m);
    return b;
}
static void BarsDestroy(void* p) {
    auto* b = (Bars*)p;
#ifdef _WIN32
    if (b->srv) b->srv->Release(); if (b->tex) b->tex->Release();
#else
    if (b->tex) glDeleteTextures(1, &b->tex);
#endif
    delete b;
}
static void BarsUpdate(void* p, const float* v) { auto* b = (Bars*)p; b->color = (uint32_t)v[0]; b->speed = v[1]; }
static void* BarsRender(void* p, void* context, double t, uint32_t* w, uint32_t* h) {
    auto* b = (Bars*)p;
    const uint32_t bg = 0xFF000000u | b->color;
    const uint32_t barX = uint32_t(std::fmod(t * b->speed, 1.0) * b->w), barW = b->w / 16, barH = b->h / 10;
    for (uint32_t y = 0; y < b->h; ++y) {
        uint32_t* row = b->px.data() + size_t(y) * b->w;
        for (uint32_t x = 0; x < b->w; ++x) row[x] = (g_showBar && y < barH && x >= barX && x < barX + barW) ? 0xFFFFFFFFu : bg;
    }
    *w = b->w; *h = b->h;
#ifdef _WIN32
    static_cast<ID3D11DeviceContext*>(context)->UpdateSubresource(b->tex, 0, nullptr, b->px.data(), b->w * 4, 0);
    return b->srv;
#else
    (void)context;
    glBindTexture(GL_TEXTURE_2D, b->tex);
    glTexSubImage2D(GL_TEXTURE_2D, 0, 0, 0, (GLsizei)b->w, (GLsizei)b->h, GL_BGRA, GL_UNSIGNED_BYTE, b->px.data());
    return (void*)(uintptr_t)b->tex;   // GL texture name (the host restores its GL state afterwards)
#endif
}

FAQ

Can I use D3D12, Vulkan or CUDA?
Only through interop you set up yourself (e.g. shared NT handles). The ABI gives you D3D11 objects; everything must end up in a D3D11 texture/view.
Can a source have its own audio?
Not in ABI 1 or ABI 2: a plugin source only produces video. Use a separate audio device, or an audio filter or output to process or receive the mixed audio.
How do I store state that isn't a number (a file path, text)?
Source and filter properties are still numeric (float, int, bool, colour). With ABI 2 (Nocto 0.8.0+) use nocto.storage: a per-plugin settings JSON document (any JSON text, up to 1 MiB, kept in Nocto's data folder and not included in scene exports or profiles) and secret storage for tokens and keys (never exported or logged). Edit such values in a dock panel built with nocto.ui (text inputs, checkboxes, combos). On older hosts (ABI 1) store the data yourself, e.g. a JSON file in your own folder.
Why isn't update / destroy / nocto_plugin_unload called?
See the notes in each section: in 0.4 source settings changes recreate the instance, filter instances live until exit, and DLLs are never unloaded. Write code that works whether or not these are called.
Will my plugin break when Nocto updates?
Not while the host supports your ABI: Nocto 0.8.0 loads ABI 1 and ABI 2 plugins unchanged. A future incompatible ABI would be announced in the release notes; a plugin reporting an ABI the host does not support is refused with a clear log message rather than loaded.
Can I ship a plugin with dependencies?
Yes, next to the DLL in the same folder (loaded with LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR). Avoid names that collide with Nocto's own DLLs.
Does the plugin work for 32-bit games / game capture?
Plugins run inside Nocto (64-bit) only; they never run inside games.
Is the HDR canvas different?
Yes: filters receive FP16 scRGB. Avoid assuming 0..1 range and avoid saturate() on colour if you want to keep HDR highlights.

/* nocto_plugin.h - Nocto plugin C ABI (version 2; ABI 1 plugins keep loading unchanged).
 *
 * A plugin is a DLL exporting:
 *     NOCTO_EXPORT uint32_t nocto_plugin_abi(void);                                   // return NOCTO_PLUGIN_ABI
 *     NOCTO_EXPORT int      nocto_plugin_load(const nocto_host* host, nocto_plugin_info* info);   // 1 = ok
 *     NOCTO_EXPORT void     nocto_plugin_unload(void);                                // optional
 * nocto_plugin_load fills `info` and registers features through `host`. Descriptors (and every string / array they point
 * to) must stay valid until unload - use static storage. Nocto copies nothing it does not need.
 *
 * DLLs are loaded from %LOCALAPPDATA%\Nocto\plugins and from the "plugins" folder next to Nocto.exe.
 * Linux: the plugin is a shared library (.so) loaded with dlopen from ~/.local/share/Nocto/plugins (or $NOCTO_CONFIG_DIR/plugins)
 * and <dir of the nocto binary>/plugins. Same ABI; only the graphics handles differ (see "Linux graphics handles" below).
 * Shader-only video filters need no DLL: a <name>.json manifest + .hlsl file (see docs/PLUGINS.md).
 *
 * Threads: sources, video filters and outputs' video callback run on the render thread with the D3D11 immediate
 * context locked (do not lock it yourself, do not block). Audio filters run on the mixer thread (10 ms chunks).
 * Outputs' audio callback runs on the audio thread. Hotkey callbacks run on the UI thread.
 * Crashes (access violations etc.) inside any callback are caught: the plugin is disabled and the error shown in
 * the Plugins window; Nocto keeps running. Do not rely on this for normal error handling.
 *
 * Properties: every feature describes its settings as an array of nocto_prop; Nocto draws the settings UI and passes
 * the current values as a float array in the same order (bool 0/1, int, colour 0xRRGGBB as float).
 */

 * features can keep returning 1 (NOCTO_PLUGIN_ABI_V1). Always check host->abi >= 2 before calling host->get_api. */

#define NOCTO_PLUGIN_ABI 2u

/* Linux graphics handles. There is no D3D11: every `device` / `context` argument is NULL and an OpenGL 3.3 core context is current on the
 * calling thread (render thread for sources / video filters / output video). The host saves and restores its GL state around each call.
 *   - "ID3D11ShaderResourceView*" = GL_TEXTURE_2D name stored in the pointer: (void*)(uintptr_t)name. Source textures are RGBA8, straight
 *     alpha, row 0 of the uploaded data = top of the picture.
 *   - "ID3D11RenderTargetView*" (video filter out) = framebuffer object name, already bound with the viewport set to w x h; draw into it.
 *   - Video output gets the canvas texture name (RGBA8, row 0 = top).
 * Video filters are called with in = texture name and out = FBO name; a filter must not keep GL objects bound. Link plugins with -lGL.
 * A crash (SIGSEGV/SIGBUS/SIGFPE/SIGILL/SIGABRT) inside a callback is caught like on Windows; do not rely on it. */

/* ---- source: produces a texture every frame ---- */
typedef struct nocto_source_desc {
    const char* id;          /* unique within the plugin */
    const char* name;        /* "Add source" menu label */
    const nocto_prop* props; uint32_t prop_count;
    /* device: ID3D11Device*. Return an instance pointer (NULL = failure). */
    void* (*create)(void* device, const float* values);
    void (*destroy)(void* inst);
    void (*update)(void* inst, const float* values);                 /* settings changed (optional) */
    /* context: ID3D11DeviceContext*. Return ID3D11ShaderResourceView* of a BGRA8/RGBA8 texture (sRGB-encoded,
       straight alpha) owned by the plugin and valid until the next call; set *w and *h. NULL = draw nothing. */
    void* (*render)(void* inst, void* context, double time_sec, uint32_t* w, uint32_t* h);
} nocto_source_desc;

     * Returns a pointer to a const API table, or NULL when the host does not know that name / version:
     *   "nocto.ui"      version 1 -> const nocto_ui_v1*        (widgets for panels)
     *   "nocto.app"     version 1 -> const nocto_app_v1*       (panels, menus, UI-thread tasks, stream state, open_url, textures)
     *   "nocto.storage" version 1 -> const nocto_storage_v1*   (per-plugin settings JSON + secret storage)
     *   "nocto.net"     version 1 -> const nocto_net_v1*       (async HTTP + WebSocket)
     * Every table starts with `uint32_t size` (sizeof the table the host filled in): fields beyond `size` do not exist. */
    const void* (*get_api)(void* plugin, const char* name, uint32_t version);
} nocto_host;


/* =====================================================================================================================
 * ABI 2
 * ---------------------------------------------------------------------------------------------------------------------
 * Threads: panel draw callbacks, menu callbacks, post_to_ui tasks, HTTP completions and WebSocket events ALL run on the UI thread
 * (inside Nocto's frame, one after another) - a plugin does not need locks for state touched only from those callbacks. Do not block
 * in them. The calls of nocto_ui_v1 are only valid inside a panel draw callback; nocto_app_v1.post_to_ui is the only call that
 * may be made from any thread. Every callback is crash-guarded like the ABI-1 callbacks (a crash disables the plugin).
 * Sizes passed to nocto_ui_v1 (widths, heights, spacing) are in "dp": 100%-scale pixels. Nocto multiplies them by the UI scale (up to
 * 300%), so never pre-scale. 0 = automatic size, negative width = stretch to the right edge leaving -width dp.
 * Colours are 0xAABBGGRR packed into a uint32_t (NOCTO_RGBA).
 * ================================================================================================================== */
#define NOCTO_RGBA(r, g, b, a) ((uint32_t)(r) | ((uint32_t)(g) << 8) | ((uint32_t)(b) << 16) | ((uint32_t)(a) << 24))
