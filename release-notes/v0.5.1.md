# Nocto 0.5.1: AMD recording fix, log dumps and bug reports

## Fixes
- **AMD: recordings no longer freeze after a few seconds while the audio keeps going.** Encoder output was only collected when a new frame was submitted. AMD's hardware encoder (Media Foundation / AMF) holds more frames than Intel's or NVIDIA's, so it could fill the GPU frame pool. Then the render thread stopped submitting, nothing collected the encoder's output, and video stopped for the rest of the recording. Nocto now collects output every few milliseconds whenever the encoder is holding frames.
- In-flight frames are now counted when the encoder actually releases them (tracked samples). Before, Nocto counted output packets, which drifted when the encoder skipped or merged frames at high capture rates.
- AMD tuning: low-latency mode, B-frames off, and quality capped at "balanced" so VCN keeps up with 100+ fps.
- **Fresh installs start with no stream destinations.** A Twitch preset no longer appears. The Stream button opens Settings > Stream so you can add one. Existing destinations are unchanged.

## New
- **Encoder watchdog**: if the video encoder stops producing output for 3 seconds while frames are going in, Nocto restarts it (and switches to another backend if it keeps failing) without stopping the recording. The file gets a short gap instead of frozen video, and audio stays in sync.
- **Help > Save log dump...**: saves one zip (Desktop by default) and opens the folder. It contains current and previous session logs, the browser-source log, encoder/drop stats, system info (OS, CPU, RAM, GPUs and driver versions, monitors/HDR), your settings with stream keys, tokens and passwords removed, and recent crash dumps.
- **Help > Report a Bug...**: offers to save a log dump first, then opens the GitHub issue form.
- Rotating logs in `%LOCALAPPDATA%\Nocto\logs` (`nocto.log` for this session plus the 4 previous ones), with detailed encoder logging (init settings, MFT errors, stalls, stats every 10 s).
- Performance panel: encoder lag and watchdog restarts, plus a recording drop breakdown (render-behind, encode backlog, encode failures) logged every 10 s.

If recording still fails on your GPU, use **Help > Report a Bug...** and attach the log dump.
