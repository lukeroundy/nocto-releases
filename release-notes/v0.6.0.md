# Nocto 0.6.0: Linux

**New: the first Linux release.** Download `Nocto-0.6.0-x86_64.AppImage` (x86_64), then `chmod +x Nocto-0.6.0-x86_64.AppImage` and run it. It was tested on CachyOS with KDE Plasma on Wayland. Windows users keep using `Nocto-Setup-0.6.0.exe` (x64) or `Nocto-Setup-0.6.0-arm64.exe` (ARM64); the Windows builds behave as in 0.5.3.

**What works on Linux**
- Screen and window capture through the desktop portal and PipeWire (Wayland native, X11 supported); desktop and microphone audio through PipeWire with the same mixer
- Recording to MP4 and streaming (RTMP and SRT) with Intel QuickSync, VAAPI, NVIDIA NVENC or software x264/x265; the encoder list follows the GPU you choose in Settings
- Replay buffer, pause and resume, multistream destinations
- The same UI as Windows, including HiDPI scaling from 100% to 300%
- The video editor with GPU effects, keyframes, masks, transitions and export
- Plugins as `.so` files (same ABI 1, OpenGL instead of D3D11), see the Plugin SDK page
- Browser sources through the built-in Servo engine, with page audio in the mixer
- Webcams and capture cards (V4L2), HDR source tone-mapping in the editor
- Virtual camera through PipeWire, or through v4l2loopback so Discord, Zoom and browsers can see it
- Global hotkeys through the desktop portal (KDE and GNOME 48+) and native file dialogs

**Requirements (Linux)**
- x86_64, a Wayland or X11 session, PipeWire and xdg-desktop-portal (KDE, GNOME and wlroots portals work)
- GPU drivers from your distribution: Mesa 24 or newer (Intel, AMD) or the NVIDIA proprietary driver. They are not bundled in the AppImage
- Recommended: the GStreamer `plugins-base` and `plugins-good` packages (audio and video in browser sources)
- Optional: `v4l2loopback` for the virtual camera in other apps, e.g. `sudo modprobe v4l2loopback exclusive_caps=1 card_label="Nocto Virtual Camera"`

**Known limits on Linux**
- No game capture hook (it relies on Windows injection); use window capture
- Frames make one trip through system memory before encoding (not zero-copy yet), so CPU use is higher than on Windows
- HDR10 output is not available (recordings stay SDR)
- No in-app updater yet: "Check for updates" opens this page; download new AppImages manually
- WebAudio is not supported in browser sources (normal audio and video elements work)
- Tested on one machine (CachyOS, KDE Plasma, Wayland; Intel Arc and NVIDIA GPUs). Other desktops, distributions and AMD GPUs are not verified yet; please report problems with Help > Report a Bug

**Windows (x64 and ARM64):** no behavior changes. The shared UI and platform code were reorganized so both platforms build from the same source.
